## 4. Things to know before P1

- **Defects found and fixed in P0** (all with rows): asn1c runtime patches 0001–0007 and compiler patches 0001–0002 (KS-PLAT-D1…D5); the NAS protected header's spare bits (KS-NAS-D1); NIA1 over an empty message read past the buffer in the vendored SNOW 3G f9 (KS-SEC-D1, refused now); the M7 ePCO two-octet lengths (KS-NAS-T3); a shard timer that could fire early (KS-PLAT-B13).
- **asn1c relay re-encoding** fails for IEs whose id the object set does not know and for values outside a non-extensible constraint, which the decoders do not check (KS-PLAT-G3). P1's entities must check what they receive by each protocol's error-handling clauses; re-encoding what was received stays a tool function.
- **Oracle limits** (pycrate 0.8.1, tshark 4.6.4, pySim) are recorded as -T rows (KS-PLAT-T15–T17, KS-NAS-T2, T5, KS-GTPU-T2, KS-UICC-T2). The pySim READ/UPDATE BINARY offset formula and tshark's P3 '00' reading are worth reporting upstream.
- **The provenance database** (`~/.cache/kaluza-sim/provenance/`) is keyed to each tree's git HEAD, so the guard fails when kaluza-core (or another tree) commits. Rebuild with `tools/provenance.py build --tree kaluza-core` (about 15 s). onomondo and the Wireshark sources are not on the dev PC (KS-PLAT-G4).
- **Local-only vectors** (the user's phone captures) live in `tests/vectors/local/`, git-ignored, with a committed hash manifest; `tools/corpus_ingest.py` rebuilds them on a machine that has the captures.
- **SIM captures** carry AUTHENTICATE results with CK, IK and Kc zeroed (`uicc::redact_keys`); the secret canary checks it.
