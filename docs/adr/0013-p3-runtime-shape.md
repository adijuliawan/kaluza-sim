# ADR 0013: P3's runtime shape

- **Status:** accepted, 2026-10-17 (user, with the P3 plan; decisions D1–D10 by their answers; the go given the same evening)
- **Context:** P3 brings mobility (intra-CU, Xn and N2 handover, wave 40 steps 1–2), the radio model and idle mode, and closes v1 (`roadmap.md`). The P2 code assumes one of everything:
  - the CU-CP holds one NG, one F1 and one E1 link, and F1 Setup takes the DU's first cell (`cucp.hpp`, `cucp.cpp`);
  - the topology refuses a second AMF, gNB, DU or cell; the aio node has one CU-CP, DU and CU-UP, and every UE sends to one DU;
  - the scripted core replaces its gNB on each new association and checks the first served TAC only;
  - the UE re-camps on any SIB1 and drops K_gNB once the AS keys exist;
  - `/v1/faults` is a constant `FAULTS=0`.
  kaluza-core's AMF serves no handover procedure yet and one TAC (its `docs/phase-3/README.md`; kaluza-core-92 and start-phase-3-plan, 2026-10-17). OCUDU d9d2263f4d serves Xn-C, N2 and intra-CU handover, without Xn-U forwarding, End Marker, or the NH/NCC from PATH SWITCH REQUEST ACKNOWLEDGE.
- **Decision:**
  1. **Topology v3** (plan design point a). It is backward compatible: every P1/P2 topology stays valid. New fields: `amfs:` (a list, each with a name and an address), `gnbs:` (a list; each gNB a list of `dus:`), `xn: mesh | <pairs>`, `neighbours: auto | <explicit>` and `radio: {view, model, seed, sites}`. **One cell per DU** (D7): a multi-cell site is several DUs, so intra-CU handover is inter-DU; intra-DU inter-cell handover is v1.x (ledger). The row set names five shapes: `1g` (the P1/P2 topologies), `1g2d`, `3g`, `3g7` (the third gNB's cells on TAC 000007) and `oc` (our gNB beside OCUDU's).
  2. **The process shape.** A gNB is a set of roles as in ADR 0011; a run holds N gNBs. The supervisor keys its children by (gNB, role), each role keeps `<run>/<gnb>-<role>/`, and the control API routes per node. On kaluza-uesim gNB n's CU-CP and CU-UP hold .30+2(n−1) and .31+2(n−1) (N2 and Xn-C, N3 and Xn-U), OCUDU keeps .36/.37 (plan design point b), and netd names each gNB's namespaces. The UE farm keeps one KAIR socket per lane per DU.
  3. **The radio seam.** `radio/replica` gets an `IRadioView`: which cells a UE hears, and at what level. R2 brings a static implementation (topology-driven, `cell power` edits), so handover work does not wait for the radio model. R15 swaps in the TR 38.901 replica behind the same interface without touching the UE or the DU. `ksim-radio` is the scene authority: it publishes a snapshot and versioned deltas and is never called per packet (tenet 4). The scene version rides in KAIR, and a mismatch is exit 7 (`cli.md`).
  4. **Xn-C sockets** (spike 1, KS-PLAT-T64). Each CU-CP has one one-to-many SCTP socket bound to its Xn address and port 38422 (TS 38.422 §7), PPID 61, which both listens and connects. OCUDU's Xn-C gateway works that way, and it accepts an association only from a configured peer address, port included. The gNB with the lower global gNB ID connects; the other only listens, so one Xn Setup runs per pair. OCUDU's own dialling is accepted as it comes. Xn-U runs on the CU-UP's N3 address, one GTP-U endpoint per local address. `gnb xn-link down` blackholes a pair at the application level, so the MobilityManager picks N2.
  5. **Handover classification** (TS 38.300 §9.2.3; plan design point e): intra-CU when the target cell is on one of this CU-CP's DUs, Xn when an Xn peer serves it and the link is up, N2 otherwise. The CLI (`gnb ho`, `xn-ho`, `n2-ho`, `ho-cancel`) and later E2 can force a kind.
  6. **The scripted core becomes multi-association.** It accepts several gNBs at once, holds AMF instances with GUAMIs of their own, checks every served TAC, serves Path Switch and N2 handover, and walks NH with **its own code**, separate from the key-chain oracle's. Its SMF/UPF switch the N3 tunnel, keep indirect-forwarding tunnels and send End Marker on the old path. Its NG-C offers 10 streams each way.
  7. **CORE_GAP** (D1, D5; plan design point g). A row whose procedure kaluza-core's own register lists as unserved is marked `kaluza=gap` in `gates/rows/p3.tsv`. `tools/p3_exit.py` names it and never counts it, backed by a baseline row's evidence (D2: today's AMF answers HANDOVER REQUIRED and PATH SWITCH REQUEST with an ERROR INDICATION by name). The marks come off when wave 40's roll serves the procedure (TAC 000007, F-83, the SUCI keys and the 999/70 seed ride the same roll).
  8. **The key-chain proof exports no key** (`requirements.md` §3.6). `tests/oracles/keychain.py` recomputes every hop from the CI test K and the public inputs in the captures (RAND, NAS COUNT, PCI, SSB ARFCN, NCC), then verifies each hop's SRB1 MAC-I with its own AES-CMAC. The canary checks that no key bytes reached a file. Against the Open5GS rig the AMF's own NH chain is the independent producer.
  9. **Faults.** A registry behind `/v1/faults`: every fault set is recorded in the run manifest, `faults list` prints `FAULTS=0` when there is none, and a gate set refuses to start otherwise. Message rules live on the existing tap wrappers and on the air (drop, delay, duplicate, ×N); link faults set loss and delay per air link; cell off/on and `ue rlf` model radio events (KS-L2R-005). Node faults use supervisor signals. The SCTP blackhole is an nft rule set by **netd v4** inside a ksim node namespace; on the dev PC, where split mode runs in the root namespace (P-64), `freeze` plus a blackholed link covers the heartbeat-timeout path. `p3_exit` refuses an exit run with a fault outside a fault row. *As built in R3* (KS-PLAT-B63, B64): the record is `<run>/faults.tsv` beside the manifest (each split role's in its directory), one line per rule set, spent or cleared with the gate row it serves; the message rules sit in their own wrappers above the capture taps, so a message dropped on send is not captured; a uu rule acts at the transmitter, where the ideal RLC's AM retransmissions and maxRetxThreshold make loss a radio link failure.
  10. **Loss across handover** is defined over the ideal RLC's "delivery confirmed": a new ledger entry, A-15. The harness counts sequence-numbered probes per handover kind; the target is 0 lost and 0 reordered on AM DRBs with forwarding, and everything else is measured and reported.
  11. **Radio determinism.** `src/radio` builds with `-ffp-contract=off`; outputs are quantised to TS 38.133's reporting ranges; scene deltas apply at scene time, not on arrival; a cross-process hash test compares the replicas.
  12. **Rows and windows.** `gates/rows/p3.tsv` holds kaluza-sim's own `ksim-p3.*` rows: p2.tsv's columns with `p3` for `p2`, plus `topology`; frozen at R0 (141 rows). The P1 and P2 rows are scored again in the P3 topologies from their own files. P3's windows are LW6+ (kaluza-core, requested from its phase-3 coordinator) and RW1+ (the Open5GS rig). Captures keep one pcapng interface per link, so the run-level files the P1/P2 gates read stay.
  13. **RRC containers built through the JER route and read by OCUDU offline** (spike 2, KS-RRC-T4). The handover CellGroupConfig (spCellConfig with reconfigurationWithSync: spCellConfigCommon, newUE-Identity, t304, contention-free RA) is built as a JER value and encoded by the generated code, as every typed builder of P1/P2 is. `tools/ocudu_vectors/unpack.sh` runs OCUDU's own decoder from the pinned tree over it: OCUDU's CU-CP calls `report_fatal_error` on a target DU's CellGroupConfig or dedicated SIB1 it cannot unpack, and reads `t304`, `t301` and `t311` from them unchecked. Every RRC container we hand OCUDU passes that check offline before any live run (R1).
  14. **Re-establishment at another gNB** needs Retrieve UE Context (TS 38.423 §8.2.6), which is P3b. In P3 it falls back to RRC setup and NAS, recorded as a -G row.
- **Consequences:**
  - The multi-association refactor touches every P1/P2 path; R2 lands it with every P1/P2 row green in CI and the virtual-time two-gNB rig first.
  - netd grows again (v4: the nft blackhole, `exec --stdin`). The user installs it on the dev PC from printed commands; it is installed on kaluza-uesim inside windows.
  - Rows that need kaluza-core's wave 40 run on the stub and the Open5GS rig and are offered as wave 40's gate contract (`docs/contract/wave-40.md` at R21).
  - The VM's 4 vCPUs carry 3 gNBs × 3 roles, OCUDU and 100 UEs in LW6; R7 measures the shape on the dev PC first, and resizing is the user's call.
