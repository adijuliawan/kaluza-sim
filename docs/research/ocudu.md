## Identity

- **What it is:** the **srsRAN Project, renamed.** `LICENSE` says "Copyright 2021-2026 Software Radio Systems Limited". `CHANGELOG` runs 23.3 → 25.10, then "26.04 (initial OCUDU release)". Linux Foundation governance.
- **Licence:** **BSD-3-Clause-Open-MPI**, permissive. kaluza-sim may copy from it, with attribution ([ADR 0004](../adr/0004-clean-room-licensing.md)).
- **Size:** C++17, CMake. About 796K lines of hand-written C++ plus about 1.0M lines of committed generated ASN.1 codecs.
- **ASN.1 is Rel-18.** RRC v18.8.0, NGAP v18.8.0, F1AP v18.8.0, E1AP v18.5.0, XnAP v18.7.0, NRPPa v18.7.0, LPP v18.1.0 (fork only). It is generated by an SRS tool that is **not in the tree**, so OCUDU's codecs can't be regenerated at Rel-19.

## Split architecture

Binaries: `gnb`, `ocu`, `ocucp`, `ocuup`, `odu` (split 6, 7.2 or 8), `odu_low`, `ru_emulator`.

| Binary | Interfaces |
|---|---|
| `gnb` | F1-C, E1 and F1-U are in-process connectors (`apps/gnb/gnb.cpp`). N2, N3, Xn-C and E2 are real |
| `ocucp` | F1-C and E1 SCTP servers (`apps/cu_cp/cu_cp.cpp`), plus Xn-C, N2 and E2 |
| `ocuup` | E1 SCTP client, F1-U over UDP, N3, E2 (`apps/cu_up/cu_up.cpp`) |
| `odu` | F1-C SCTP client, F1-U over UDP, E2 (`apps/du/du.cpp`). Southbound: UHD/ZMQ (split 8), OFH (7.2) or the FAPI plugin (split 6) |

There is no O-RU PHY. A separate RU means real hardware or `ru_emulator`.

## Simulation hooks

| Hook | What it gives |
|---|---|
| **ZMQ radio** (`lib/radio/zmq`) | One REQ/REP socket pair per antenna port, complex-float IQ at full sample rate, blocking lock-step. No channel model, no multi-UE combiner |
| **Radio plugins** (`lib/radio/plugin_radio_factory.cpp`) | `dlopen`s `libocudu_radio_<driver>.so` with factory `ocudu::create_dynamic_radio_factory`: the clean place for an external IQ or channel emulator |
| Real-time loopback radio; dummy RU; DIFI serialization | Timing checks only |
| **Test mode** (`lib/du/du_high/test_mode`, `configs/testmode.yml`) | "Phantom" UEs inside the DU, with RNTI, CQI/RI/PMI and auto ACK/CRC. In the fork, `f1c_du_test_mode_adapter.cpp` fakes the CU's answers, so **these UEs never reach the CU-CP or the AMF** |
| `no_core` mode | A stub that only answers NG Setup; no GTP-U |
| `ru_emulator` (`apps/examples/ofh/`) | OFH timing windows and sequence checks; UL/PRACH with random payloads (transport fidelity only) |
| Amarisoft TRX (`utils/trx_ocudu`) | Amarisoft UE over ZMQ |
| Test harnesses | `tests/integrationtests/du_high/test_utils` (`du_high_env_simulator`, `du_high_ue_simulator`: UEs at MAC-PDU level with a dummy CU-CP); `tests/integrationtests/du_high_cu` |

- our DU ↔ `ocucp`/`ocuup` over F1 (P2);
